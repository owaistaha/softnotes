Read this whole file before touching code. It is the single source of truth
for what this app is, what already exists, what the reference video shows,
and the order the remaining work happens in. Update the **Status** checklist

---

## What this app is

A minimalist notes app for iPhone, built in **Swift + SwiftUI only**, that
recreates the UI, UX, transitions and animations of a reference screen
recording (a concept app shown in 7 labelled sections: 01 Home, 02 Tab bar,
03 Pick an icon, 04 Write a chit, 05 Save, 06 Fold, 07 File it away).

The whole product in one loop:
1. Home shows a soft 3D folder (latest note icons floating above it, a note
   count, a "Notes" toggle) and a short Recent list.
2. Tap the black `+` → a 3-step compose flow: pick a pastel icon → write a
   short note ("chit") on a paper card → save.
3. On save, the card folds in half and physically files itself into the
   folder on Home. The count ticks up and the note appears in Recent.

The motion is the product. A screen that looks right but moves generically
is not done.

## Stack

- iOS **17.0+**, iPhone only, portrait only, **light mode only** (forced in
  `SoftNotesApp`).
- SwiftUI, Observation (`@Observable`), no UIKit unless SwiftUI genuinely
  can't do something (keyboard avoidance is the one likely exception).
- **Zero third-party dependencies.** No SPM packages.
- Xcode 16+ (the previews use `@Previewable`).
- Project file generated by **XcodeGen** from `project.yml` — never
  hand-edit `.xcodeproj` / `project.pbxproj`.
- Swift language mode **5** (not 6) for now, to avoid strict-concurrency
  noise while the UI is being built. Revisit later.
- No persistence yet — `NotesStore` is in-memory with sample data.

## Before you start

### Only the human can do these
- Install **Xcode 16 or newer** from the App Store and open it once (it
  installs components on first launch).
- Accept the Xcode license if prompted: `sudo xcodebuild -license accept`
  needs their password — ask them to run it, don't try.
- Copy the reference recording into the repo at
  `Reference/reference-walkthrough.mov` (the original file was named
  `ScreenRecording_09-30-2026_01-58-05_1.mov`). Without it you can't
  compare frames — ask for it if it's missing.
- Running on a **physical iPhone** needs their Apple ID selected as the
  signing team in Xcode. Simulator runs need nothing.

### Claude Code can do these itself — don't ask, just do them
- `brew install xcodegen ffmpeg` (skip if `which xcodegen` / `which ffmpeg`
  already succeed).
- Write `project.yml`, run `xcodegen generate`.
- Build with `xcodebuild`, boot a simulator, install and launch the app.
- Take simulator screenshots (`xcrun simctl io booted screenshot out.png`)
  and extract reference frames with ffmpeg to compare against.
- All file creation / edits under the source folders.

## Bootstrap sequence (do this first, top to bottom)

1. **Locate the sources.** Run `find . -name "*.swift" -not -path "*/.build/*"`.
   The expected layout is below (it may sit at the repo root or inside a
   `SoftNotes/` folder — use whatever is actually there; do not move files
   around just to match this doc).
2. **Create `project.yml`** next to the source folders, adjusting `sources`
   paths to what step 1 found:

   ```yaml
   name: SoftNotes
   options:
     bundleIdPrefix: com.owaistaha
     deploymentTarget:
       iOS: "17.0"
     createIntermediateGroups: true
   settings:
     base:
       SWIFT_VERSION: "5.0"
       MARKETING_VERSION: "0.1.0"
       CURRENT_PROJECT_VERSION: "1"
   targets:
     SoftNotes:
       type: application
       platform: iOS
       sources:
         - path: App
         - path: DesignSystem
         - path: Models
         - path: Features
       settings:
         base:
           PRODUCT_BUNDLE_IDENTIFIER: com.owaistaha.softnotes
           TARGETED_DEVICE_FAMILY: "1"
           GENERATE_INFOPLIST_FILE: YES
           INFOPLIST_KEY_UILaunchScreen_Generation: YES
           INFOPLIST_KEY_UISupportedInterfaceOrientations_iPhone: UIInterfaceOrientationPortrait
           INFOPLIST_KEY_UIUserInterfaceStyle: Light
           ENABLE_PREVIEWS: YES
   ```
   Also add a `.gitignore` covering `*.xcodeproj/xcuserdata`, `DerivedData/`,
   `.DS_Store`, `build/`. Commit `project.yml`; the generated `.xcodeproj`
   can be committed or ignored — ask the human which they prefer if unsure.
3. `xcodegen generate`.
4. **Discover a simulator — don't hardcode one:**
   `xcrun simctl list devices available | grep iPhone` and pick the newest
   iPhone (Pro, non-Max preferred — the reference is a ~393pt-wide phone).
5. **Build:**
   `xcodebuild -project SoftNotes.xcodeproj -scheme SoftNotes -destination 'platform=iOS Simulator,name=<found device>' build`
6. **Hard gate — the existing code has never been compiled.** It was written
   without a Swift toolchain. Fix every compile error *before* starting any
   new feature. Likely suspects are listed under **Known risks** below. Fix
   minimally; don't redesign while fixing.
7. Boot the simulator, install, launch, screenshot Home. Extract the matching
   reference frame (`ffmpeg -ss 12.5 -i Reference/reference-walkthrough.mov -frames:v 1 ref_home.png`)
   and compare side by side. Note visible differences in the Status log.
8. Only then continue with the **Roadmap**.

### Architecture (must stay true)

```
RootContainerView (ZStack)
├─ Theme.Palette.canvas (ignoresSafeArea)
├─ tabContent: HomeView | SavedView      ← recedes (scale .94, blur 14, opacity 0) while composing
│    └─ .safeAreaInset(.bottom): FloatingTabBar  (+ FAB in its top overlay)
└─ ComposeFlowView (if isComposing)       ← in-place overlay, NOT a sheet / fullScreenCover
```

State owned by the container: `store`, `selectedTab`, `isComposing`,
`isFolderOpen`, `folderFrame`, and `@Namespace flowNamespace`.

Key invariants:
- **`FlowID.primaryAction`** is the matched-geometry id shared by the Home FAB
  (`+`) and the compose Next button (`→`). Exactly one view with that id may
  be *present* at a time — the FAB is removed (`if !isCollapsed`) when
  compose shows. Both state changes must happen inside the same
  `withAnimation` transaction or the morph breaks.
- The FAB is positioned with `.alignmentGuide(.top)` (not `.offset`) so its
  *layout* frame is where it's drawn — matched geometry reads layout frames.
  Don't swap that for an offset.
- **`isFolderOpen` semantics:** `false` = folder closed = toggle **ON**
  (lavender, knob right). `true` = open = toggle OFF (grey, knob left),
  front panel hinged forward, chips lifted. Home idles closed. The fold
  animation opens it to receive, then closes it.
- **`FolderFrameKey`** publishes the folder card's frame in `.global`
  coordinates from HomeView → read in the container → passed to compose as
  `folderFrame`. The fold animation flies to this rect.
- **Chip slots:** `folderPreview[0]` (newest) → centre, `[1]` → left,
  `[2]` → right/highest. Changing the array animates the shuffle.
- The container's `file(_:)` already runs the Home half of the save
  choreography: close compose + open folder → 420 ms → `store.add` (chip
  drops, count rolls, folder bounces, row blur-slides in) → 380 ms → close
  folder. The fold flight gets layered *in front of* this, not instead of it.

## Design spec (measured from the reference video)

### Tokens (all already in `Theme.swift` — use them, never raw hex in views)

| Role | Value |
|---|---|
| Canvas background | `#F0F0F0` |
| Surface (cards, rows, round buttons) | `#FFFFFF` |
| Recessed track (tab bar, toggle off) | `#E7E6E8` + inner shadow |
| Ink (text, FAB) | `#17161A` |
| Secondary / tertiary text | `#8E8C93` / `#C2C0C6` |
| Toggle on | bg `#DCD4FF`, text `#7B6FE0` |
| Paper (note card) | `#FBF8EE` |
| Progress arc on Next button | amber `#F5B74A` |
| Pastel tones (base / light) | lavender `#9087FD/#CBC6F7`, pink `#FD84A6/#F8C2D2`, blue `#6CABFD/#B3D2FC`, orange `#FFA962/#FFD6B0`, green `#6ED39A/#BDEBD0`, yellow `#FFCF5C/#FFE7A8`, indigo `#7E80F7/#C4C5FB` |

Springs (`Theme.Motion`): `snappy` 0.35s/0.25 bounce (small UI state),
`smooth` 0.55s/0.12 (screen swaps), `bouncy` 0.6s/0.38 (things landing),
`release` 0.7s/0.45 (let go of a drag). Add a new named spring here if a
new feel is needed — don't inline one-off springs in views.

## Roadmap (do in order; one step per session is fine)

**Step 1 — Compile & baseline.** Bootstrap sequence above. Home + tab bar
must match the reference screenshot closely.

**Step 2 — Compose state.** Add `Features/Compose/ComposeDraft.swift`:
`@Observable final class ComposeDraft { var step: ComposeStep; var icon: NoteIcon; var text: String; var tags: [String] }`
with `enum ComposeStep: Int { case pickIcon = 1, write, save }`. Container
creates a fresh draft on each `startComposing()`. Back goes to the previous
step (or closes on step 1); close always cancels. Next is disabled on
`.write` while text is empty.

**Step 3 — 03 Pick an icon.** `Features/Compose/IconPickerStep.swift`.
Replace the stub body of `ComposeFlowView` with a step switch; steps swap
with `.blurFade`. Keep the Next button + nav bar in `ComposeFlowView`, not
inside each step, so they persist across steps.

**Step 4 — 04 Write a chit.** `Features/Compose/NoteCardView.swift` (the
paper card, reused by Save and Fold) + `WriteStep.swift`. `TextField(axis: .vertical)`
with `@FocusState`; auto-focus shortly after the step appears. Keyboard
avoidance: let SwiftUI's safe area do it where possible.

**Step 5 — 05 Save + 06 Fold + 07 hand-off.** The hard one. Suggested shape:
- A `FoldPhase` enum (`idle, lift, fold, push, drop, landed`) driven from the
  container with `withAnimation(_:completionCriteria:_:completion:)` (iOS 17)
  or a `Task` with `Task.sleep` between phases — one timeline, one place.
- A `FoldingCardView` rendering the card as two halves (same content,
  masked to top/bottom halves); the top half gets
  `rotation3DEffect(-180°·t, axis: x, anchor: .bottom, perspective: ~0.5)`
  with a darkening overlay, swapping to a plain paper "back" past 90°.
- The flight lives in a top-level overlay in `RootContainerView` above
  both Home and compose, positioned in global space so it can travel into
  `folderFrame`.
- During the push, Home must be **visible** (not opacity 0) and scaled
  ~1.5× with its anchor at the folder's centre (compute a `UnitPoint` from
  `folderFrame` vs screen bounds), then scale back to 1×.
- "Behind the front panel": simplest is a mask/clip at the folder's body-top
  line during the drop, plus a blur ramp.
- Finish by calling the existing `file(_:)` logic (adjust its delays so the
  chip landing lines up with the icon arriving — don't duplicate it).

**Step 6 — Polish pass.** Frame-by-frame comparison against the reference
for every section; tune `Theme.Motion` and geometry only through tokens.
Reduce Motion path for the whole fold (see Hard rules). VoiceOver pass.

**Later / explicitly out of scope until asked:** note detail/edit screen,
search, "See all" screen, persistence (SwiftData or a JSON file), dark mode,
iPad, widgets, sync, custom fonts. Don't start these on your own.

## Hard rules

- **Use the design system.** Colours from `Theme.Palette` / `PastelTone`,
  springs from `Theme.Motion`, fonts from `Font.soft*`, cards via
  `SoftSurface`, buttons via `.pressable`. No raw hex, no inline one-off
  springs in feature views.
- **Never stack `.shadow()` modifiers on a content view for card depth** —
  chained shadows compound (each shadows the previous). Use `SoftSurface`,
  which draws one shape copy per shadow layer.
- **Compose stays an in-place overlay.** Moving it into `.sheet` or
  `.fullScreenCover` kills the FAB→Next morph and the fold flight (they
  need a shared coordinate space and namespace). Don't.
- **Keep the FAB/Next matched-geometry contract** (see Architecture). If you
  add a new Next-like button, it gets its own id.
- **Every animation respects Reduce Motion.** `@Environment(\.accessibilityReduceMotion)`:
  idle floats stop (already done), tilt still works (user-driven), the fold
  becomes a simple cross-fade + count roll. Never an infinite animation
  without that check.
- **Verify SF Symbols exist on iOS 17** before using one (there's no
  cherry or rocket symbol — that's why `basket.fill` / `paperplane.fill`
  are used). A missing symbol renders blank silently.
- **Don't change a token to fix one screen.** If Home needs a different
  shadow, that's a new `Elevation` case, not an edit to `.raised`.
- Every view file keeps a working `#Preview`. If a preview needs the store,
  inject `.environment(NotesStore())`.
- **Build after every meaningful change** and fix warnings you introduced.
  Don't stack three features on an unbuilt tree.
- Don't hand-edit the `.xcodeproj`; change `project.yml` and regenerate.
  New files under the source folders are picked up by `xcodegen generate`.
- Don't rename `SoftNotes`, the folders, or public type names without
  asking — the human imports these files between chat and Claude Code.
- Copy in the UI: sentence case, plain verbs. The button that says "Save"
  produces "Saved" — keep action names consistent.

## Known risks in the current code (check these at Step 1)

- **Never compiled.** Expect a handful of small errors.
- `RootContainerView`: `.onPreferenceChange` closure mutating `@State` can
  warn/error under strict concurrency — fine in Swift 5 mode; if needed,
  wrap the assignment in `Task { @MainActor in … }`.
- `FolderCard.frontPanel`: the open hinge uses `-16°` about the x-axis. If
  the panel tips *away* from the viewer instead of toward, flip the sign.
- `FolderCard` tilt is a `simultaneousGesture` inside a `ScrollView`; with
  `.scrollBounceBehavior(.basedOnSize)` Home shouldn't scroll on normal
  phones. On an SE-size device, check that tilt and scroll don't fight.
- `StackedIconView` front tile uses `.ultraThinMaterial`; if it looks grey
  instead of glassy on the canvas, increase the tint opacity rather than
  removing the material.
- Relative times in `Note.samples` are computed from `.now` — "2h ago" can
  read "Yesterday" just after midnight. Expected, not a bug.
- Font: SF Pro with negative tracking approximates the reference's grotesk.
  Only swap to a custom font if the human supplies one.

## Definition of done (v1)

On an iPhone simulator, a person can: launch to Home (matching the
reference screenshot) → switch to Saved and back (pill slides) → tap `+`
(it morphs into Next) → pick an icon → write "Have a good day" on the paper
card with the keyboard → save → watch the card fold in half and file itself
into the folder → see the count go 8 → 9, the toggle flip on, and "Have a
good day — Just now" appear at the top of Recent. Every transition runs
smoothly with no layout jumps, and with Reduce Motion on the same flow works
with simple fades.
