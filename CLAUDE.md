# CLAUDE.md — SoftNotes (soft-UI notes app, native iOS)

Read this whole file before touching code. It is the single source of truth
for what this app is, what already exists, what the reference video shows,
and the order the remaining work happens in. Update the **Status** checklist
at the bottom after every step you finish.

---

## What this app is

A minimalist notes app for iPhone, built in **Swift + SwiftUI only**, that
recreates the UI, UX, transitions and animations of a reference screen
recording (a concept app shown in 7 labelled sections: 01 Home, 02 Tab bar,
03 Pick an icon, 04 Write a chit, 05 Save, 06 Fold, 07 File it away).

The whole product in one loop:
1. Home shows a soft 3D folder (latest note icons floating above it, a note
   count, a "Notes" toggle) and a short Recent list.
2. Tap the black `+` → a 3-step compose flow: pick a pastel icon → write a
   short note ("chit") on a paper card → save.
3. On save, the card folds in half and physically files itself into the
   folder on Home. The count ticks up and the note appears in Recent.

The motion is the product. A screen that looks right but moves generically
is not done.

## Stack

- iOS **17.0+**, iPhone only, portrait only, **light mode only** (forced in
  `SoftNotesApp`).
- SwiftUI, Observation (`@Observable`), no UIKit unless SwiftUI genuinely
  can't do something (keyboard avoidance is the one likely exception).
- **Zero third-party dependencies.** No SPM packages.
- Xcode 16+ (the previews use `@Previewable`).
- Project file generated by **XcodeGen** from `project.yml` — never
  hand-edit `.xcodeproj` / `project.pbxproj`.
- Swift language mode **5** (not 6) for now, to avoid strict-concurrency
  noise while the UI is being built. Revisit later.
- Persistence (Step 7): notes live in a versioned JSON file (no SwiftData) — see "Persistence" below.

### Only the human can do these
- Install **Xcode 16 or newer** from the App Store and open it once (it
  installs components on first launch).
- Accept the Xcode license if prompted: `sudo xcodebuild -license accept`
  needs their password — ask them to run it, don't try.

- Take simulator screenshots (`xcrun simctl io booted screenshot out.png`)
  and extract reference frames with ffmpeg to compare against.

## Bootstrap sequence (do this first, top to bottom)

1. **Locate the sources.** Run `find . -name "*.swift" -not -path "*/.build/*"`.
   The expected layout is below (it may sit at the repo root or inside a
   `SoftNotes/` folder — use whatever is actually there; do not move files
   around just to match this doc).
2. **Create `project.yml`** next to the source folders, adjusting `sources`
   paths to what step 1 found:

   ```yaml
   name: SoftNotes
   options:
     bundleIdPrefix: com.owaistaha
     deploymentTarget:
       iOS: "17.0"
     createIntermediateGroups: true
   settings:
     base:
       SWIFT_VERSION: "5.0"
       MARKETING_VERSION: "0.1.0"
       CURRENT_PROJECT_VERSION: "1"
   targets:
     SoftNotes:
       type: application
       platform: iOS
       sources:
         - path: App
         - path: DesignSystem
         - path: Models
         - path: Features
       settings:
         base:
           PRODUCT_BUNDLE_IDENTIFIER: com.owaistaha.softnotes
           TARGETED_DEVICE_FAMILY: "1"
           GENERATE_INFOPLIST_FILE: YES
           INFOPLIST_KEY_UILaunchScreen_Generation: YES
           INFOPLIST_KEY_UISupportedInterfaceOrientations_iPhone: UIInterfaceOrientationPortrait
           INFOPLIST_KEY_UIUserInterfaceStyle: Light
           ENABLE_PREVIEWS: YES
   ```
   Also add a `.gitignore` covering `*.xcodeproj/xcuserdata`, `DerivedData/`,
   `.DS_Store`, `build/`. Commit `project.yml`; the generated `.xcodeproj`
   can be committed or ignored — ask the human which they prefer if unsure.
   **Done:** sources started flat at the repo root and were moved (`git mv`)
   into the folders below before Step 2, so `project.yml` lists them
   explicitly (`App`, `DesignSystem`, `Models`, `Features`; new files inside
   those are picked up automatically). Don't use `path: .` — it would pull
   the UI-test sources into the app target. The `.xcodeproj` is git-ignored
   (regenerate it), as is `Reference/*.mov`.
   **Never put DerivedData inside the repo** (e.g. `-derivedDataPath build/…`):
   XcodeGen scans the source path, finds the built app's `Info.plist`, sets
   it as `INFOPLIST_FILE`, and the build fails with "Cycle inside SoftNotes".
   Use the default DerivedData location or a path outside the repo.
3. `xcodegen generate`.
4. **Discover a simulator — don't hardcode one:**
   `xcrun simctl list devices available | grep iPhone` and pick the newest
   iPhone (Pro, non-Max preferred — the reference is a ~393pt-wide phone).
5. **Build:**
   `xcodebuild -project SoftNotes.xcodeproj -scheme SoftNotes -destination 'platform=iOS Simulator,name=<found device>' build`
6. **Hard gate — the existing code has never been compiled.** It was written
   without a Swift toolchain. Fix every compile error *before* starting any
   new feature. Likely suspects are listed under **Known risks** below. Fix
   minimally; don't redesign while fixing.
7. Boot the simulator, install, launch, screenshot Home. Extract the matching
   reference frame (`ffmpeg -ss 12.5 -i Reference/reference-walkthrough.mov -frames:v 1 ref_home.png`)
   and compare side by side. Note visible differences in the Status log.
8. Only then continue with the **Roadmap**.

### Architecture (must stay true)

```
RootContainerView (ZStack)
├─ Theme.Palette.canvas (ignoresSafeArea)
├─ tabContent: HomeView | SavedView      ← recedes (scale .94, blur 14, opacity 0) while composing;
│    │                                     on save: zoomed ×1.3 on the folder, rises from below
│    └─ .safeAreaInset(.bottom): FloatingTabBar  (ZStack(.top): track padded down + FAB)
├─ ComposeFlowView (if isComposing)       ← in-place overlay, NOT a sheet / fullScreenCover
└─ FoldStage (always mounted, zIndex 2)   ← save → fold overlay, full-screen global space
```

State owned by the container: `store`, `selectedTab`, `isComposing`,
`isFolderOpen`, `folderFrame` / `homeFrame` / `screenSize` (frozen while
composing or saving — Home is transformed then), the save state
(`foldPhase`, `foldCard`, `landing`, `pendingNote`, `landingNoteID`,
`heldNoteID`, `saveTask`), and `@Namespace flowNamespace`.

Key invariants:
- **`FlowID.primaryAction`** is the matched-geometry id shared by the Home FAB
  (`+`) and the compose Next button (`→`). Exactly one view with that id may
  be *present* at a time — the FAB is removed (`if !isCollapsed`) when
  compose shows. Both state changes must happen inside the same
  `withAnimation` transaction or the morph breaks.
- **Matched pairs need asymmetric transitions** (learned by measuring, Step 3):
  `PrimaryActionButton.morphTransition` = `.asymmetric(insertion: .identity,
  removal: .opacity)`, applied to the FAB *and* to the **container** that is
  inserted/removed around Next (a transition on a child of an inserted
  container is ignored). Why: the inserted view starts opaque on the old
  view's frame, the removed view survives (fading) to hand that frame over.
  Both `.identity` = the view *pops* (nothing left to match); both default
  (opacity) = a glide that dips ~40% see-through mid-flight; a blur-fade on
  a parent that also contains Next dissolves it. Same rule for any future
  matched pair. Known residual — **close (Next → FAB) is not a morph**:
  60 fps frames (probe after Step 3) show Next fading out *in place* (~130 ms,
  no movement), then the + appearing already at home, half-transparent, and
  fading in (~80 ms). Matched geometry isn't pairing on close even though the
  FAB already has `morphTransition` (so that isn't the cause), and it isn't
  Home's opacity (probed). Unresolved; the reference never shows a close.
  Probe next time with `scripts/video-frames.sh` on the close window.
- `ComposeFlowView` stays in the hierarchy permanently (`isPresented`), and its
  Next button lives in a layer *outside* the blur-fading content (nav + step).
- **Keyboard (rewritten in 6B — this was the main-thread hang):** SwiftUI's
  keyboard safe area drives the avoidance; it is the only source that moves
  in step with the keys (the iOS 26 keyboard is out of process and
  `keyboardWillChangeFrame` arrives ≈100–150 ms into its rise — padding from
  UIKit alone lagged the keys on video). `keyboardOverlapPadding()` wraps
  compose in a `GeometryReader` whose frame IS the proposal, reads the edge
  from the proxy while computing the padding (**no state written during
  layout**), and pins the content to exactly that frame, bottom-aligned, so
  overflow goes up and never resizes anything. The Step 4 version stored its
  own bottom edge from a GeometryReader `onChange`; with the keyboard up the
  write step is taller than the space left, so the padding made the view
  overflow and re-centre, the edge moved by half the padding, and the 80pt
  cap turned that into an endless cycle (587 → 611 → 623 → 0 → 587…) inside
  one `render()` — the "Timed out while evaluating UI query" hang. The same
  overflow enlarged the root ZStack, and THAT was the "44pt lip" Step 4
  corrected: with it fixed, SwiftUI's keyboard edge equals UIKit's top on
  iOS 26.5 (539 = 539) and 17.5 (482 = 482). The correction stays, gated by
  the measured overlap (0 on both), capped at 80pt.
- **Rules that came out of it:** never write state from a geometry read
  without an equality check (and rounding); never measure a view whose size
  can depend on what you set from the measurement — measure something whose
  size is fixed by its parent (a `GeometryReader`, a `.frame(maxWidth:
  .infinity, maxHeight: .infinity)` that can't be exceeded), or read the
  proxy in the body instead of storing it.
- **Text-field caps:** clamp in the binding's setter *and* re-set one tick
  later (`WriteStep.textBinding`); clamping in `onChange` or only in the
  setter leaves the field showing too much. Verify with one-key-at-a-time
  typing (`testTextCapAndFit`) — XCUITest's burst `typeText` outruns it.
- The FAB is positioned by layout, not `.offset`: `FloatingTabBar` is a
  `ZStack(alignment: .top)` whose track is padded down by half the FAB's
  outer diameter (`PrimaryActionButton.outerDiameter / 2`), so the FAB's
  centre sits on the track's top edge and its *layout* frame is where it's
  drawn — matched geometry reads layout frames. Don't swap that for an
  offset, and don't go back to `.alignmentGuide`: explicit guides don't
  survive `.matchedGeometryEffect` (that's why the FAB rendered centred
  inside the bar before Step 1b).
- **`isFolderOpen` semantics:** `false` = folder closed = toggle **ON**
  (lavender, knob right). `true` = open = toggle OFF (grey, knob left),
  front panel hinged forward, chips lifted. Home idles closed. The fold
  animation opens it to receive, then closes it.
- **`FolderFrameKey`** publishes the folder card's frame in `.global`
  coordinates from HomeView → read in the container → passed to compose as
  `folderFrame`. The fold animation flies to this rect.
- **Chip slots:** `folderPreview[0]` (newest) → centre, `[1]` → left,
  `[2]` → right/highest. Changing the array animates the shuffle.
- **The fold has ONE timeline:** `RootContainerView.save(_:)` is the only
  place `foldPhase` changes — it sleeps to `FoldTimeline` times (one
  `ContinuousClock` start, no drift) and wraps each phase change in its
  `Theme.Motion` animation. Views only *read* the phase (ComposeFlowView: nav
  back/away, Next drop, no hit testing; WriteStep: unfocus, hide its card,
  title away; FoldStage: everything else). Don't add timers or delays in views.
- **`FoldStage` is Animatable and always mounted.** It converts the phase into
  five progress values (settle, lift, fold, push, drop) and SwiftUI
  interpolates *them*; every frame's card position/pose, icon position/size/
  shape and flap angle is computed from those in one place. A newly inserted
  view can't animate from an old value, which is why the stage stays mounted
  and only its content is inserted/removed (`.identity` both ways).
- **No `Canvas` in the flight.** The drop mask (front-panel cutout) is a
  `Shape` with an even-odd fill. A full-screen `Canvas` mask is rasterised on
  the CPU every frame and delayed the save's first frames by ≈0.5 s (every
  phase then looked early on video).
- **Hand-off without a double:** at the tap the stage's card appears exactly
  on the write card (same unposed global frame from `draft.cardFrame`, same
  pose), and the write card hides *in the same frame* with a
  `transaction(value:)` that strips the animation — a plain `.opacity` change
  inside the tap's spring faded it out behind the flying card (seen on video).
- **The icon is one view:** the stage hides the card's header icon
  (`showsHeaderIcon: false`, slot kept) and draws a single `StackedIconView`
  at 82pt scaled to 32pt on the header slot, then lifts it (scale → 1) to the
  top edge, then rides the flap's top edge down to the fold line.
- **Split card without a seam:** each half is the whole card clipped by
  `CardHalf` — `bleed` past the card on the outer sides (keeps its shadow),
  the bottom half reaching 1pt up under the top half *inside* the card.
  `FoldingCardTests` checks it: at 0° the split equals the plain card
  (max channel diff ≤ 2 on whole points), and the hand-off frame equals the
  resting write card except inside the icon.
- **The save's Home half is part of the same timeline** (the old `file(_:)`
  bridge is gone). At `.folded`, out of sight and with no animation, compose
  closes (the FAB re-inserts inside the *hidden* tab bar — no morph, no dip),
  Home is set up zoomed ×1.3 on the folder, 500pt below, folder open, header/
  Recent/tab bar hidden. The store does not change until `.landed`.
- **Home's zoom is a transform, not a layout:** `scaleEffect(anchor:
  .topLeading)` + `offset`, computed from the *frozen* untransformed frames
  (`homeFrame`, `folderFrame`) so the centre chip slot lands at 0.549 of the
  screen height. The landing point is computed from `FolderCard`'s static
  geometry (`chipCenter(_:in:isOpen:floatStart:)`, `frontPanelFrame(in:)`)
  through the same mapping — never guessed. Measure `screenSize` as
  `frame.maxY + safeAreaInsets.bottom`: on iOS 26 the proxy of an
  `ignoresSafeArea` view reports the *inset* size (the zoom landed 50pt high).
- **Landing = one object:** the landing waits for the drop animation's
  completion (`withAnimation(…, completionCriteria: .logicallyComplete)`),
  then in ONE transaction removes the flying icon and adds the note; the new
  chip is inserted with `.identity` (`landingNoteID`) exactly where the icon
  ends (48 × zoom, chip shape — the icon morphs squircle → circle via
  `StackedIconView.cornerFraction`, float start included). Chips are drawn
  newest on top (`zIndex`): drawn underneath, the old centre chip hid the
  hand-off for 3 frames. Verified on video: the icon's centroid closes on the
  slot and the swap frame changes no more than its neighbours.
- **Empty centre slot:** at `.folded` (out of sight, no animation) Home is
  told `vacatesCentreChip`: chips move one slot along (centre → left, left →
  right, right leaves), so the push shows two chips like the reference and
  at `.landed` every old chip is already in its final slot — nothing crosses
  the landing chip. Shuffling at the push start showed the leaving chip
  rising into view (video, 6A).
- **Count leads the store:** from `FoldTimeline.countRoll` the count bubble
  shows `store.count + countLead` (1), so it rolls while the icon is still
  flying (reference); `countLead` returns to 0 in the landing transaction.
  The folder's receive bounce follows `receivedCount` (the real store
  count), NOT the displayed count: the landing point is computed for the
  folder at rest, and bouncing before the landing would move the chip off
  the icon.
- **Recent holds the new row** (`heldNoteID`) until `.rowEntry` — the
  reference shows the two old rows through the zoom-out and slides the new
  one in ≈1.8 s after the landing.
- **Folder drag on short screens (6B):** Home measures content vs viewport;
  when it scrolls (iPhone SE with three Recent rows) `FolderCard` gets
  `sharesDragsWithScroll`: the tilt drag starts after 20pt (at 4pt it beat
  the scroll view's pan and Home couldn't be scrolled from the folder) and a
  drag whose first movement is vertical belongs to the scroll view (no tilt).
  Where Home fits, the tilt is unchanged (4pt, any direction). A
  long-press-then-drag gesture also swallowed the scroll (tested).
- **Reduce Motion (6B):** fold → cross-fade + count; picker ring fades per
  cell (no glide), preview swaps with a fade; folder receive bounce off,
  chips fade in/out; tab pill fades; idle floats off; tilt stays.
- **VoiceOver (6B):** rows read "<title>, <relative time>" (one element);
  picker cells use spoken names (`NoteIcon.accessibilityName`); the note
  field is "Note" with a hint; filing posts one announcement "Note saved.
  N notes." (`announceFiled()` — landing, Reduce Motion, fast-forward).
  App text does NOT follow Dynamic Type: every font is a fixed
  `.system(size:)` token (checked at default / XXL / AX5 — nothing clips
  because nothing grows). Scaling is an open design decision.
- **Note detail (Step 8):** tapping a row (Home Recent, Saved) opens `NoteDetailView`, an in-place overlay
  owned by `RootContainerView` (`detail: DetailSession?` — id, the row's global frame, the tab, and a
  `ComposeDraft(editing:)` edit buffer). No sheet. It reuses `NoteCardView`/`NoteCardContent` (new
  optional `onIconTap`; compose passes none), `IconPickerStep(draft:)` for the icon grid, `cycleTag()`,
  `ComposeDraft.sanitized` (48-char cap, same one-tick-later clamp as `WriteStep.textBinding`) and
  `keyboardOverlapPadding()`. Edits go to `NotesStore.update(_:_:)` as they happen (debounced like every
  mutation; no-op when nothing changed). Empty text on leaving the field restores the text from when the
  field got focus (and writes it back — typing had committed every non-empty intermediate); never a delete.
  Delete = trash → `confirmationDialog` → card fades/shrinks (`Theme.Motion.snappy`) → `store.delete` →
  overlay closes. iOS 26 shows that dialog as a popover with no Cancel button (tap outside); iOS 17 shows Cancel.
- **The open/close flight is ONE progress value `t`** (0 = at the row, 1 = open), animated with
  `Theme.Motion.smooth`: the card grows from `startScale` 0.3 with its centre placed so its header-icon
  slot starts exactly on the row's icon (both frames are MEASURED: the row via `onGeometryChange` in
  `NoteRow`, the card's resting frame from its own `onGeometryChange`, which also starts the open —
  event-driven, no delay). The icon is `FlightIcon` (Animatable in `t`: position, 40 → 32pt, glow 1 → 0.5,
  rotation 0 → −3°); the card's header icon is hidden (`showsHeaderIcon: false`) while it flies and the two
  swap in one frame (no animation) when the flight ends / starts. The source row hides its icon through
  `\.detailSourceNoteID`. Closing flies back only if the row is still listed (an unsaved note leaves Saved:
  cross-fade). Reduce Motion: 0.25 s cross-fade (`crossFade`), no flight. Measured on 60 fps video (6B
  tooling): the icon starts on the row's icon, no gap, no double, ≈0.48 s to rest; the swap frame changes
  pixel mass ≈3% and position ≈0.5px; close mirrors it and lands on the row slot (508.5 vs 509.1 at 402px).
- **Don't give the card icon a hit-area margin (Step 8):** the text field's accessibility frame is the
  bounding box of the −3° rotated card and reaches up to the icon; with an 8pt margin (even up/left/right
  only) `XCUIElement.tap()` / a VoiceOver activation on the text field opened the picker. The icon's tap
  target is its 32pt.
- **Backgrounding mid-save fast-forwards** (`finishSaveNow()` on
  `scenePhase == .background`): the task is cancelled, the note is added once
  if it hadn't landed, and everything is put in its end state without
  animation. Nothing can dismiss compose during a save (no hit testing).

### Persistence (Step 7)

- File: `Application Support/SoftNotes/notes.json`, `{"version": 1, "notes": [...]}`, dates ISO 8601
  with milliseconds (reads without too), written atomically on a background serial queue.
  `NotesStore(persistence:)` takes a `NotePersisting`; production = `FileNotePersistence.standard`,
  tests = temp directory or `InMemoryNotePersistence`. `NotesStore(notes:)` = previews (no writes).
- The store is created ONCE in `SoftNotesApp` and injected into `RootContainerView(store:)` — a
  `@State` initial value is re-evaluated whenever the view struct is rebuilt, which would load or
  seed repeatedly.
- Seeding: only when there is no file AND `hasSeeded` (UserDefaults) is unset; an emptied list stays
  empty. A mutation (`add`, `toggleSaved`, `delete`) only marks the store dirty and re-arms a 300 ms
  debounce — no encoding, no I/O — so the save timeline's animation closures may call it. The
  landing's `store.add` is therefore written exactly once. `flush()` (write now, wait) runs when
  `scenePhase != .active`, AFTER `finishSaveNow()` so a fast-forwarded note is included.
- Unreadable / unsupported-version file: moved to `notes.corrupt-<UTC stamp>.json`, store starts
  empty, `hasSeeded` set (never re-seeded); if the move fails, writes are disabled so the file is
  never overwritten. Notes that can't be decoded are skipped (only a title and a date are
  required) and the original is first copied to `notes.partial-<stamp>.json`. Unknown SF Symbol →
  `doc.text`, unknown tone → lavender, unknown shape → squircle.
- DEBUG launch args: `-resetStore` (delete file + seeded flag), `-inMemoryStore` (no disk; every
  UI test except the persistence ones launches with it), `-emptyStore` (mark seeded: zero notes;
  use with `-resetStore`). The demo flows (`-demoSave`, `-demoFold`, `-keyboardCycles`) are
  in-memory unless `-persistDemo` is also passed.
- Empty states: zero notes → no chips, bubble "0", Recent reads "No notes yet. Tap + to write your
  first one."; Saved keeps its empty state. Folder label: "1 note" / "N notes".

| Role | Value |

## Test & screenshot loop (use this in every step)

`SoftNotesUITests` is a UI-test target (defined in `project.yml`, sources in
`SoftNotesUITests/`). Tests tap through the app and attach screenshots
(`XCTAttachment`, `.keepAlways`) — including timed bursts at ~0 / 150 / 300 /
600 ms after a tap, with the *actual* capture time in the file name — so
motion can be inspected frame by frame. The script also turns off the simulator's hardware keyboard
(`ConnectHardwareKeyboard`) so the software keyboard shows — if Simulator.app
was already running with it connected, quit Simulator.app once
(`osascript -e 'quit app "Simulator"'`) for it to take effect. Tests that need
Back/× on the write step must first press Done (`leaveTextFieldIfFocused()`),
because the nav hides while typing.
Buttons the tests need carry
`accessibilityIdentifier`s (`primaryAction` is the Home FAB *and* the compose
Next button; `composeBack`, `composeClose`; picker cells `iconCell_<0…11>`,
preview `iconPreview`; write step `noteText`, `tagChip`). Don't put an
identifier on a container — it overrides its children's.

```
scripts/ui-shots.sh                 # run all UI tests, export screenshots
scripts/ui-shots.sh <testMethodName>  # run one (e.g. testFabMorphOpenAndClose)
```

It runs `xcodebuild test` (simulator: `SIM_NAME`, default "iPhone 17 Pro"),
writes DerivedData and the `.xcresult` under `$TMPDIR/softnotes-uitests/`
(never inside the repo), then `xcrun xcresulttool export attachments` and
copies every screenshot to **`build/shots/ui/<attachment name>.png`**
(git-ignored). Look at them with the Read tool; tile bursts with ffmpeg
(`ffmpeg -i a.png -i b.png … -filter_complex hstack`).
Add a test (and its identifiers) for every new interaction you build.
To measure a motion, script it: e.g. find the FAB disc's centroid and
darkness per frame (a solid ink disc reads ≈ 23 on a 0–255 gray scale).

**Screenshots are for settled states, video is for motion.** Each screenshot
takes 50–300 ms (slower on busy screens), so a "0/150/300/600 ms" burst really
lands at 0/330/490/690 ms — the file name carries the actual time, but don't
judge a 300 ms animation from it. For motion use the recording:

```
VIDEO=1 scripts/ui-shots.sh testMotionForVideo   # records build/shots/ui/motion.mov (60 fps)
VIDEO=1 scripts/ui-shots.sh testWriteMotionForVideo   # keyboard rise, typing, save
scripts/video-disc-track.py  build/shots/ui/motion.mov   # FAB/Next disc: centre + opacity per frame
scripts/video-ring-track.py  build/shots/ui/motion.mov 27 40   # picker selection ring per frame
scripts/fab-morph-stats.py   build/shots/ui 01_ 03_      # same disc measure on screenshots
scripts/video-frames.sh build/shots/ui/motion.mov 33.40 33.75 out.png 1 1206:560:0:2000 7
                            # tile frames by tracker time (step, crop, columns)
```
The trackers print one line per *change*; a glide is a run of intermediate
positions over several frames, a pop is a single jump, a dissolve is `core`
(darkness) drifting up (23 ≈ solid ink). Times in their output are frame
indices / 60 — **don't** feed them to `ffmpeg -ss` (screen recordings are
variable-frame-rate, seeks land seconds off); use `scripts/video-frames.sh`,
which selects frames on the same time base. Note `ui-shots.sh` wipes
`build/shots/ui/` on every run — copy anything you want to keep to `build/shots/`.
Add a test to `testMotionForVideo` (or a new one) for every new animation.

**Recordings are "changed frames only".** `simctl recordVideo` writes a frame
only when the screen changes, so a 90–300 ms gap in the raw timestamps is a
*still* screen, not a stall (checked with a deliberately slow fold). The
fps=60 resample repeats the last frame across the gap — fine for timing,
but a phase that starts right after a hold shows its first frame late by
at most one frame.

**Re-runs:** `scripts/ui-shots.sh` re-runs every failed test ONCE and prints
`RETRY: … passed on the second run (flaky)` or `… failed again`; the run
fails only if a retry fails. **The write-step "Timed out while evaluating UI query"
was an app hang, fixed in 6B** (see Architecture → Keyboard): before, 5 of
21 write-step runs hung > 32 s; after, 0 in 60+ runs and 22/22 of the suite
on the first attempt. If it ever comes back, reproduce with the tools below
rather than retrying.

**Stall tools (6B):** every UI test launches with `-watchdog` (DEBUG main-
thread watchdog → os_log). `scripts/stall-stress.sh ITER label tests…`
repeats tests with `-test-iterations`, streams the watchdog log and runs
`sample` on the app when a stall passes 2 s (hang_*.txt in
`$TMPDIR/softnotes-stress`). `-keyboardCycles N` (DEBUG) makes the app
focus/dismiss the write card N times by itself and publish a summary
(`keyboardCycleReport`), plus a probe log of SwiftUI's keyboard edge vs
UIKit's; `testKeyboardCyclesNoStalls` runs 20 cycles under XCUITest and
asserts no stall > 500 ms. Don't `sample` during a measurement you trust —
attaching pauses the app (it registers as a stall).
**Other runtimes:** `SIM_NAME="iPhone 15 Pro" SIM_OS=17.5 scripts/ui-shots.sh …`
(a bare name resolves to the latest OS only);
`SIM_NAME="iPhone SE (3rd generation)" SIM_OS=26.5` for the SE tests.
Also: Spotlight indexing of the `build/` videos loaded the host (mds_stores
≈280% CPU) and made the recorder drop whole phases — `build/` and
`build/shots/` carry `.metadata_never_index`.
Tests using `-demoFold` wait ≈4 s (`waitOutDemoKeyboard()`) before their
first query. Save tests key off `saveInFlight` — an accessibility element
that exists only while a save is in flight ("Saving note" for VoiceOver).

Unit tests (`SoftNotesTests`, hosted in the app) render views off-screen with
`ImageRenderer` and diff pixels: `scripts/ui-shots.sh SoftNotesTests/FoldingCardTests`
(any argument with a `/` is passed to `-only-testing` as is). Renders and an
amplified diff are attached (`fold-rest-*`, `fold-handoff-*`).

Launch arguments (DEBUG only):
- `-demoSave` — on the compose flow's write step, Next on an *empty* card
  saves a demo note (with the icon picked in step 1) instead of staying

- `-demoFold` — opens compose on the write step with "Have a good day"
  typed, waits for the keyboard, then runs the whole save exactly as Next

  `VIDEO=1 scripts/ui-shots.sh testDemoFold`. Tests: `testDemoFold` (count,

- `-reduceMotion` — forces the Reduce Motion paths (sets SwiftUI's

## Hard rules

- **Use the design system.** Colours from `Theme.Palette` / `PastelTone`,
  springs from `Theme.Motion`, fonts from `Font.soft*`, cards via
  `SoftSurface`, buttons via `.pressable`. No raw hex, no inline one-off
  springs in feature views.
- **Never stack `.shadow()` modifiers on a content view for card depth** —
  chained shadows compound (each shadows the previous). Use `SoftSurface`,
  which draws one shape copy per shadow layer.
- **Compose stays an in-place overlay.** Moving it into `.sheet` or
  `.fullScreenCover` kills the FAB→Next morph and the fold flight (they
  need a shared coordinate space and namespace). Don't.

## Known risks in the current code (check these at Step 1)

- **Never compiled.** Expect a handful of small errors.
- `RootContainerView`: `.onPreferenceChange` closure mutating `@State` can
  warn/error under strict concurrency — fine in Swift 5 mode; if needed,
  wrap the assignment in `Task { @MainActor in … }`.
- `FolderCard.frontPanel`: open hinge direction verified correct at Step 1
  (tips toward the viewer); reduced from −16° to −6° in Step 1b.
- `FolderCard` tilt is a `simultaneousGesture` inside a `ScrollView`; with
  `.scrollBounceBehavior(.basedOnSize)` Home shouldn't scroll on normal
  phones. On an SE-size device, check that tilt and scroll don't fight.
- `StackedIconView` front tile uses `.ultraThinMaterial`; if it looks grey
  instead of glassy on the canvas, increase the tint opacity rather than
  removing the material.
- Relative times in `Note.samples` are computed from `.now` — "2h ago" can
  read "Yesterday" just after midnight. Expected, not a bug.
- Font: SF Pro with negative tracking approximates the reference's grotesk.
  Only swap to a custom font if the human supplies one.
